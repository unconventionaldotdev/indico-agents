# review-indico-frontend

Check the touched `client/`, `templates/` and `.scss` files and run the UI once.

## React

- Plugin hooks are fetched once (`const hooks = getPluginObjects('onX')`) outside the loop that runs them.
- A wrapper that preconfigures a field spreads the inner `propTypes` (`...FinalPersonLinkField.propTypes`).
- Object properties with static names use dot access (`options.has_no_files`); optional chaining (`data?.count || 0`) over `(data && data.count) || 0`; a count comes back as `count` and lands in `numX`.
- Id lookups use a plain object, not a `Map`, unless measured.
- A conditional field is rendered or not; never `type: 'hidden'` to blank it.
- Persisting UI state (filters) in local storage: one `useEffect` with `[]` loads it once; saving happens in the change handlers, not in a second effect watching the state.
- Native mechanism first (`setCustomValidity` over custom submit interception).
- Search existing components in core and official plugins before writing one (list inputs, country dropdowns, `isoToFlag`); copy and adapt rather than reinvent.
- Only the HTTP call goes inside `try/catch`; bugs in surrounding code must surface.
- Explicit `edit ? await axios.patch(...) : await axios.post(...)` over picking a method reference.
- Dialog open state lives in the parent (`editItem` state); no `cloneElement` trigger wrapping. One `Confirm` for the selected item, with the item's identifier in state, never one rendered per row (a boolean flag opens all of them and the last one wins).
- One-click actions that are hard to undo get a confirmation dialog; a mode that users repeat (linking several occurrences) is not exited after one success.
- Inputs are disabled while their data loads (`disabled={loading}`); test with a `time.sleep(3)` in the controller.
- Component names match what they are (`TemplateManagement`, not `Router`); prefer named exports so the import site shows the real name. Components are `function` declarations, not expression-bodied arrows (`export default function X({...}) {}`), so a statement can be added while debugging.
- Components used by one module stay in that module, not in the global `react/components` index.
- Data for a dropdown loads once with `useIndicoAxios` (`{manual: true}` when not always needed) plus an explicit "refresh" button, not on every open; a refetch on open also retriggers dependent effects (previews).
- Filter semantics: a single selected value matches every item containing it; a "multiple values" filter is a separate option. Verify with real data before review.
- Lists of options come from the data the server sends (default templates), never a hardcoded list; the "blank" or default choice goes first.
- Read values from props and state where they are needed instead of threading them through several method parameters.
- No flash of empty state between load and render; pass existing data in instead of refetching; verify the loader is visible with a slowed request.
- After a mutation update local data or show "new entries available, refresh" rather than a full page reload or a refetch that resets the view.
- Reuse an existing action to reset a flag instead of adding one.
- Shared helpers move to `indico/web/client/js/react/util/` and get imported; no copies.
- Selectors keep boolean fallbacks (`staticData.paid || false`) for keys absent in other modes; no unrelated fallback removals. Props absent outside a mode are optional with a `null` default, never `isRequired`; props a connected selector always supplies are `isRequired` with no `defaultProps` entry. PropTypes match the value (`string` for a string enum, not `bool`); a PropTypes warning is fixed by widening the type at the component, not silenced.
- Optional text fields never send `''`: `nullIfEmpty` on the field, `onlyIf` in the serializer, `reason || undefined` when the edit payload is built by hand (a nicer validation error than "field cannot be null").
- Sections with no value are not rendered (`{reason && this.renderReason(reason)}`); no empty boxes.
- `FinalDropdown` gets only non-default props (no `hideValidationError`, `multiple={false}`, `search={false}`). Setting descriptions say when, not whether ("Specify when a booking reason must be provided.").
- Lists sort with natural order: `new Intl.Collator(undefined, {numeric: true, sensitivity: 'base'})` and `collator.compare`.
- A value-to-value mapping is an object lookup (`{category: 'categoryId', ...}[groupBy]`), not a `switch`; `if (!attr) throw` when validation is wanted.
- Dates from the server are formatted with `toMoment(x).format('L')`, never a raw date string. Literal punctuation in JSX is text (`(`), not `{' ('}`; check braces that leak into the output (`{'}'}`).
- An icon that looks like an expander expands something; struck-through text for invalid items; `overflowY: 'auto'`, not `scroll`.
- Selection state is filtered against the current list so deleted items drop out; name id sets `xIds`.
- Optional payload keys are omitted (`selected ? {ids: selected} : {}`), never sent as `[]`.
- Format with biome (unquoted object keys where valid).
- Redux: actions are verbs (`toggleX`, `addLater`), state slices and props are nouns or booleans (`showX`, `earlier`). Mode-specific state lives in that mode's slice. Thunks read `getState()` instead of taking state as parameters. A value the action never carries is a constant in the reducer, not `action.x || false`; no fallback for state that is always initialized.
- Build request params per branch (`let url, params, body;` then one block per mode), not by accumulating across steps.
- Mode-specific filters, controls and refetch triggers are gated on the mode (`state.linking.type && ...`); leaving the mode clears its state and refetches the regular data.
- Filtered modes replace the list on every fetch instead of merging; no endless scrolling on heavily filtered results (fires immediately, duplicates on rapid toggling).
- Range controls show the current range ("Showing bookings up to N days before the event") and sit at the top and bottom of the list; link text names the action ("Load earlier bookings", not "Load more"). `PluralTranslate` even when the count is never 1 in English.
- Clickable `<a>` gets `href="#"` plus `preventDefault` so it is tabbable.
- Show the parser's own error (`JSON.parse` message) instead of a generic one.
- Persisting filter state (`localStorage` name) is optional; skip it where remembering filters makes no sense.
- No `#id` filter on objects without a friendly id.
- Test with large datasets (thousands of rows) before claiming a list scales; filter on input is fine for small lists only. Watch the request log: a view must not fire a chain of requests on load.
- Two visual states at most: actionable (white, with button) and not actionable (greyed, no button); a third shade confuses users.
- Remove what the change made redundant (a `title` replaces `TooltipIfTruncated`; one combined string instead of two tooltips).
- No no-op handlers (`preventDefault` on elements without default behavior).
- `styleName` over `className` + `:global()`.
- Consistent casing with the endpoint; with few fields prefer snake_case over `camelize` exceptions.
- All user text through `Translate` / `Translate.string`.
- Exported components destructure props in the signature; optional callbacks are optional in the body too: define the handler unconditionally and pass `cb ? handler : null`, never `const handler = cb && (() => ...)`.
- `FinalField` with `validate={null}` must keep the default required validator.
- Pure helpers at module level, not inside the component. Short named handlers above the JSX (`refresh`) over inline dispatch calls; the name says what it does, not what it looks like.
- No `console.debug` or other debug leftovers in the diff.
- A comparison token that is not a timestamp (last update plus an "undone" marker) is named so nobody parses it as one; compare with `!==` when the value never decreases.
- When concurrent edits outdate the view, every action is disabled, the comment form included; verify by changing state in a second tab. A prop that resets a form's state is a bug to understand, not a reason to leave the form enabled.
- `if (!show) return null;` before the JSX instead of wrapping the whole tree in `show && (...)`; keeps the diff reviewable.
- Local imports go before the stylesheet import; imports with side effects (stylesheets) go last since they cannot be auto-sorted. Shared components come from the `indico/react/components` re-export, not deep paths.
- JSX works in `.js` files; never `React.createElement(...)` by hand.
- Handlers start with guards (`if (busy) return;`) and keep the main path flat. Optional params are explicit (`position = undefined`). Never `return` a value the caller ignores.
- Changing a shared component (date picker year range) is checked in every consumer (room booking); new wrapper props go in the component's `PROP_BLACKLIST` so they never reach the wrapped library component. Defaults stay generic, consumers narrow (`yearsBefore={0}`).
- Popups and pickers close when their trigger is clicked again or on an outside click; when the outside-click handler fires before the trigger's own click, check `button.contains(evt.target)` and set an ignore flag for the next click, never a timeout. A date picker opens on the period currently displayed, not on today.
- A row that looks clickable toggles its checkbox from anywhere in the row; a pointer cursor only where clicking does something. Icons next to truncatable text get `flex-shrink: 0`.
- Generated color palettes are deterministic per id, vary hue first and saturation/brightness after, derive the text color from the background by a contrast rule, and are checked visually for near-identical neighbours.
- Lists with a special first item (the current container) are tested where that item has no own entries (the Home category).
- `useSelector(selector)`, not `useSelector(state => selector(state))`; `items.find(...)`, not `const [x] = items.filter(...)`.
- Never call `form.change` during render; use `useEffect`. Unset with `undefined`, not `null` (some field types reject `null`).
- Destructure every prop the component reads; `...rest` is only for pass-through.
- Form-wide derived state (hidden fields) is computed once in a logic-only component (`useFormState` plus a dispatch to redux), never by subscribing every item to form state. Check with React DevTools "Highlight updates" while typing.
- Coupled inputs (pick a field, then a value whose options depend on it) are one custom component driven by final-form state, not two fields with local `useState`.
- Per-type behavior (`showIfOptions`, `getDataForCondition`) lives in the field registry, not in `if/else` chains on `inputType`.
- Ambiguous short labels get an i18n comment: `/* i18n: Form field */` above the attribute (plain comment, not `{/* */}`). Labels follow cardinality ("Has value" / "Has values").
- A `ready` flag in state avoids flashing items that will be hidden once conditions resolve.
- Management views never hide items; they mark them with an always-visible icon plus tooltip and a background that changes when the condition is unmet. Icon size and alignment match the existing ones (locked, retention).
- Options the user must not pick stay visible but `disabled` in dropdowns. A toggle button that is on but locked keeps `active` and adds `disabled`, so its state stays visible.
- `full_width_base.html` only when the content needs the width; check the page on a wide screen before switching the base template.
- Function names follow the component spelling (`checkboxShowIfOptions`); PropTypes are the real type (`PropTypes.array`, not `node`).
- Selectors returning a function are nouns (`getPriceFormatter`, not `getFormatPrice`); no `_` prefix on locals unless shadowing a module name.
- `<Translate>` with `<Param>` inside JSX; `Translate.string` only outside markup.
- Prices are formatted locale-aware through one shared formatter that takes the item (so price and currency travel together), never `price + ' ' + currency` or `toFixed(2)`.
- Legacy jQuery code uses `$T.gettext(...)`, not `$T(...)`, and arrow functions; prefer `data-*` attributes on the trigger over an `ajaxDialog({...})` call.
- Explicit over computed when nothing varies (`defaultActiveIndex={[0]}`); when an extension point makes it vary, name the hook.
- Validators return their message; skip range validators on values the user did not change (manager-set values may be out of range). A validator handles `undefined` itself (early return in `maxLength`) instead of every call site guarding `value !== undefined &&`.
- After renaming a key or enum member (`contribution` to `contrib`), grep every TypeScript consumer; the compiler does not catch string-keyed lookups.
- New TypeScript code questions each `moment` use; native `Date` and `Intl` cover most needs.
- Dates and times are formatted locale-aware: `Intl.DateTimeFormat` with `locale.replace('_', '-')` and `formatRange` for ranges, or the existing helpers (`serializeDateTimeRange`); never hardcoded `ha` or 24h formats. Components that format dates render only after the locale is initialized.
- Client-side search over lists spreads the values into `searchableFields` (`...persons`), never `join('')`, which matches across concatenated names.
- Generalizing a behavior into a shared component (`FinalDropdown` search) means auditing every usage: option `text` may be missing or not a string; fall back to the default behavior rather than disabling the feature per consumer. Check the library's own option (`deburr`) before writing the logic.
- Conditionally rendered `Final*` fields unregister on unmount and lose their value; hide with CSS or keep mounted.
- Identifier inputs reject spaces and uppercase; help text states the real uniqueness scope.
- Dialogs autofocus the first input; related short fields share a row.
- Mount React from a custom element (`customElements.define('ind-...')`) with attributes, not `window.setupX()` plus inline script. No `window.` prefix on globals (`URL.createObjectURL`).
- Nothing loads from a CDN (pdf.js worker, editor assets): ship it through webpack (`CopyWebpackPlugin` into `dist/js`, `workerSrc` pointing there). A heavy module is lazy-loaded behind a wrapper component with a `Loader` (`await import(...)` in `useEffect`), the inner component reusing `Wrapper.propTypes`.
- Admin-only code goes in its own bundle (`module.json` `partials: {admin: './admin.js'}`, page bundles `module_x.admin.js`) so regular pages do not load it. Empty `index.js` files are deleted.
- `Translate.string('Template "{title}" was added', {title})`, never a template literal inside `Translate.string`.
- Inside an SPA, redirect with `useHistory().push(url)`, never `location.href`. Deletions use `RequestConfirmDelete` with `persistent` and a `requestFunc` that returns `true` on error after `handleAxiosError`; the component handles the busy state, so no own `submitting` flag.
- Multi-value text inputs split on `,` and `;`; a dropdown that acts as a text input hides its icon (`icon=""`).
- Unmounting a FinalForm drops its state; no `form.reset()` on cancel. A one-line redux action is duplicated under a fitting name rather than reused under a misleading one.
- A tooltip with a date shows just the date in a `<time>` element, no translatable "On {date}". Destructure related values together (`const {createdDt, modifiedDt} = block`).
- `data-*` attributes carry values the JS reads (sorting text), never an object repr.
- No new features in the `WTF*` legacy wrappers; new behavior is React-based.
- Field values stay light (identifiers only); extra data is resolved server-side, not through callbacks that leak field internals.
- New components are generic (a file drop that hands the file to a callback), not bound to one workflow.
- Async requests behind a button (`preview`) go through `try/catch` with `handleAxiosError`; a failed submit closes overlays that would hide the error.
- Labels are plain words and reuse the existing term ("Venue", not "Location"); messages one concrete sentence. `PluralTranslate` for anything with a count.
- No labels on dropzones; fix error display another way.
- Test long content, truncation, empty states.
- A component shared across modules takes its URL builders as props (`getAllURL`, `createURL`, `editURL`); module-specific params are bound in the caller's closure, never known to the component. Generic widgets take a render prop (`actionView` receiving the item) instead of a config object enumerating use cases.
- `{count && <X />}` renders `0` when the count is zero; coerce with `!!list?.length`. `data || []` turns a pending or failed request into the empty mode; gate on `data !== null`. A component must render while fetched data is still `null` (`data?.map(...)`); an exception during the first render unmounts the tree. No loader for a request that is always fast; loaders for slow ones appear after about 500 ms so fast responses do not blink.
- Dialogs with a form use `FinalModalForm`, never `FinalForm` plus `Modal` assembled by hand; submit buttons are `FinalSubmitButton`. Every button of a new dialog is clicked once; the cancel button sets the open state to `false`. A dialog opened from imperative code is mounted with `injectModal` resolving a promise, not a global `CustomEvent` on `window`.
- After `location.href = ...` in a submit handler, `await new Promise(() => {})` so the form never leaves the submitting state. Defer to the next tick with `_.defer(...)`, not `Promise.resolve().then(...)`. No lodash for what the platform provides (`Object.keys`, `Object.values(x).some(...)`), and no reimplementation of what a dependency in use provides (`_.range`, `nanoid`).
- A dummy entry injected for the empty case (`id: -1`) must not be confused with a real single entry: branch on the raw list, and use the same condition on every surface that pads.
- No hardcoded allowed-extension lists in the client when a configurable mechanism exists; restrictions are data enforced server-side. Help text is dropped when the control already enforces the constraint or the explained feature is secondary.
- `UserSearchTokenContext.Provider` and a `search-token` attribute only when the mounted tree contains a user search widget.
- Mount custom elements with `CustomElementBase.defineWhenDomReady(...)`; custom elements that mount React in `connectedCallback` unmount it in `disconnectedCallback`; they are registered once from `indico/web/client/js/index.js`, components use the tag without importing the element module; siblings in `custom_elements/` import each other relatively. A custom element rendered from JSX reacts to every attribute React may change after mount (`observedAttributes` plus `attributeChangedCallback`). Boolean attributes are written `attr={flag || undefined}` and read with `hasAttribute`; the raw attribute string never reaches a boolean prop. Attributes the component stopped reading are removed from the element and the template.
- Cross-module imports use the `indico/modules/...` alias, never `../../../` paths climbing out of the module. Imports from `indico-url:` end in `URL` and match the endpoint name (`sessionBlocksURL` for `api_session_blocks`).
- Placeholder values never rendered are plain strings, not `Translate.string`; a `defaultProps` value nobody relies on is not translatable either (`''` or `null`). Converting a `.jsx` to `.tsx` drops `propTypes`; every prop lands in a typed interface and unused props or types are removed. No branch for values the TypeScript type rules out.
- A field wrapper passes `FinalField` only the props it needs; forwarding `{...props}` with `description` renders it twice. Wrapped final-form fields pass `onFocus` / `onBlur` to the inner input (and call both on non-input interactions like a trigger click) so `touched` works and errors show on blur; `required` yields a distinct "Please provide the X" message per sub-field; `value` may be `null` under `allowNull`.
- Generic loop variables are `x`; event handler parameters are `evt`, never `e`. Counts are `xCount` or `numX`, never `numberOfX`. Only components are PascalCase; plain functions are camelCase, also in registries. Arrow functions for callbacks and returned closures, never `function()` expressions. Boolean dispatch is an `if / else if / else` chain, never `switch (true)`.
- Surrounding punctuation sits outside `<Translate>` / `<PluralTranslate>`. A sentence is one translatable string, never assembled from translated fragments; one `PluralTranslate` per sentence with `<Singular>`, `<Plural>`, `<Param>`. Interpolated titles are quoted (`'View the "{title}" category'`), aria labels included. Product and format names ("Google Wallet", "PDF") are not translated.
- Sentence case in every user string including placeholders and options; option labels do not repeat the widget type ("Expanded", not "Expanded dropdown"); the field label names what is displayed. Short hints carry no trailing period; full sentences do. Status messages speak from the user's side ("Your data is being prepared. We will notify you by email ..."); "by email", not "via email". Source strings are American English ("Program", "Analyze").
- UI state over a list is keyed by the item's natural key (`{[date]: expanded}`), not array indexes; a curried handler (`onClick={handleHeaderClick(date)}`) replaces index bookkeeping. React `key` values are stable and unique per item (`file.path`, an id stored at creation), never `nanoid()` or `Math.random()` in render, never `file.size`, never a value the user can edit into a duplicate; a single element outside a list gets no `key`.
- Follow the library's documented composition (one `Accordion` holding every `Accordion.Title`/`Accordion.Content` pair). A control inside a clickable header calls `evt.stopPropagation()` with a comment naming the parent handler it blocks. Buttons inside a form that do not submit get `type="button"`; primary actions use `primary`, not `color="blue"`.
- No side-by-side radio buttons: a mode selector uses the widget sibling fields use (`FinalDropdown`); a two-state option is a `FinalCheckbox` `toggle` worded so the default is unchecked. No hover styling on non-interactive text; a new field aligns with its sibling fields. Decorative elements that convey nothing are removed; a widget variant matches its sibling in icon placement and alignment.
- The PropTypes shape of API data lists exactly the keys the current payload carries. Object-valued props use `PropTypes.shape({...})`, never `PropTypes.object`; keys that may be empty are not `isRequired`.
- Function components with hooks only; no new class components. A `useEffect` registering a listener returns the cleanup; `eslint-disable` comments name the rule. State updated through a chain of transformer functions is `useReducer`. A selector fallback is a module-level constant (`const EMPTY_DATA = {}`), never a literal inside the selector.
- Dates cross component boundaries as ISO `YYYY-MM-DD` strings (`PropTypes.string`); consumers convert at the edge with `serializeDate` / `toMoment`; no moment or `Date` objects where siblings take strings. A possibly empty date string is parsed with `toMoment(value, format)`, never `moment(value, format)`. Date-only values never go through `new Date('yyyy-mm-dd')` or `toISOString()` (UTC shift); `toLocaleDateString('en-CA')` with a comment saying why. Constants are `export const ISO_FORMAT`, never hung on a function object.
- A date picker's contract: `value` in and `onChange` out are ISO strings; `format` only drives display, parsing and the hint, defaulting to the locale (`moment.localeData().longDateFormat('L')`); the initial value is reformatted before it reaches the text input. Free-text input is reformatted once it parses; two-digit years are rejected. A hand-written parser lives in its own module under `utils/`. A picker's invalid-input sentinel never reaches consumers expecting a date or `null` (`invalidValue` prop); validators compare against it, side-effect handlers skip it.
- The current locale comes from Indico (`moment.locale()`), never from the browser; first day of week and weekend days come from locale data (`new Intl.Locale(name).weekInfo`), never hardcoded Monday; translation directory names convert to BCP 47 (`de_DE` to `de-DE`). Nothing time- or locale-dependent is computed at module load (`const TODAY = ...`); compute it in the handler or as a default parameter. No fallback chains for values the page always sets.
- Date bounds are declarative props (`min`, `max`, `rangeStartMin`, `rangeEndMax`), not a per-date callback; when a bound depends on another field, track that field as state and pass the bound. A `min` shorthand on a range sets both sides' minimum; a side's min and max are never the same value. Each bound has its own helper encoding its rule; a date bound is never derived by truncating a time bound. A `min`/`max` on one control that another path bypasses (year input vs calendar navigation) is enforced on both.
- Locking one end of a range (`startDisabled`) applies to its input, its trigger and the dialog's state machine; restoring state on close reapplies the lock. A prop ignored because a precondition is missing emits `console.warn`. `readOnly` (the form does not let the user change it) and `disabled` (temporarily unavailable) are two props; a `readOnly` picker also disables its triggers. `disabled` reaches every interactive child of a composite input and matches the SUI look next to it.
- A text input paired with a picker stays typeable: only the trigger button opens the picker. When the dialog closes, focus returns to the trigger, never to a text input. Clicking the already-selected day keeps it selected and advances; it never deselects. Hovering a day previews the resulting range; one pure selection function drives preview and click in both the field-based and the inline picker. A multi-month calendar never shows the same date twice. An inline calendar reflects the pending selection before "Apply". A widget's calendar is its own custom element (`<ind-calendar>`) with its own React wrapper.
- The calendar grid is a `role=listbox` of `role=option` buttons with roving `tabIndex`, `aria-selected` per day and `aria-disabled` outside the bounds; arrow keys leaving the month switch it and focus the target day. A `querySelector` that can match nothing is null-checked. A mode change inside a picker is announced through an `aria-live` region or a visible indicator. A format hint screen readers need stays in the DOM under `%visually-hidden`; a `placeholder` alone is not announced. Sub-labels with an obvious default (`rangeStartLabel`) are optional with translated defaults; where space is tight the label stays in the DOM visually hidden, never removed, and trailing `:` is not rendered when the label is empty.
- Popups position inside the viewport and above sticky navigation (`position: fixed`, clamped); a popover opens above the trigger when there is no room below; no full-screen portal fallback. A `position: fixed` popup inside a transformed ancestor (a centered modal) is offset: fix in that page's stylesheet. Text derived from state (toggletip counts, live regions) is checked after navigating inside the widget. Controls with no alternative activation on touch devices stay visible.
- When one form field alternates between a single-date and a range picker, the single variant adapts its value to the range shape through a thin wrapper and the validators unwrap it, so the stored value shape never changes with the mode.
- Replacing a library component removes its dead props at every consumer (`disabledDate={() => false}`, `initialVisibleMonth`), its constants imports, the CSS targeting its classes (`:global(.DateRangePicker_picker)`) and callbacks only it called.
- Initial values derive from the data present (`fileData[htmlName]`), not from a mode flag (`isUpdateMode`), so plugins can prefill in other modes. A missing optional value renders nothing, never an invented label ("Unlisted"). Links never force a new tab (`target="_blank"`), except links rendered inside an editor preview.
- Pagination controls hide what cannot change the view: no page-size picker when the smallest size fits every row, and only sizes below the row count plus "all". An empty list keeps the surrounding controls (search box, count) and shows a message where the rows would be; long names stay on one line with an ellipsis. Tabs and groups keep the order managers configured. Layout magic numbers get a comment with the reason; a value built in two statements becomes one `const` expression.
- Inputs for code-like values (regexes, URL patterns) use a monospace font. Legacy JS keeps its `$('html').data('static-site')` branch around anything that opens a dialog. A comment describing a group of declarations moves with them.
- Build-time scripts (`preval`) follow the runtime lint style and skip unexpected input (an unofficial locale directory) with `try/catch` plus `continue` and a comment.

## SCSS

- Dialog and list heights relative to the viewport use `vh`, not `em`.
- Classes that exist for JavaScript carry the `js-` prefix (`js-popup-container`); styling classes never double as hooks.
- A `.module.scss` that is all `:global` is a plain `.scss`; it never styles document-wide elements (`body`). `:global(.lib-class)` rules nest inside the component's own class, never at the top level.
- No inline `<style>`; reuse existing classes before adding new ones.
- Never widen or restyle shared legacy classes (`exclusivePopup`); scope through `ajaxDialog({dialogClasses: 'editor-output'})` or a module stylesheet.
- Markup and classes on event display pages are a public API for custom stylesheets: keep element types (`span.conference-title-link`) and floats, test against events with custom CSS, and ship a new layout behind an opt-in setting with the old CSS as default.
- No structural selectors into a third-party component's DOM (`> div:first-child > div > div`); add a class to the target element. Semantic elements (`<b>`) over single-purpose utility classes (`.bold`).
- Styles of a single widget go in a `.module.scss` used through `styleName`, or nest under a unique root (the custom element tag); bare class names collide across pages. Class names are kebab-case, in CSS modules too. Rules sit under the element they style (`ind-date-picker` vs `ind-calendar`); check the compiled output.
- Every bundle's main stylesheet forwards the reset first (`@forward 'base/reset';` before design-system `@use`s); check the reset before zeroing margins or padding. `@use 'base/palette' as *;` for shared partials, never `@import`.
- SUI styling leaks into nested controls of a widget placed inside `.ui.form`; the widget matches the size and density of neighbouring SUI controls, and the overrides are wrapped in named mixins so the debt can be found later. A custom element's disabled and hover styling lives in its own stylesheet, never inherited from a framework ancestor (`.ui.field`).
- Hovering an already-selected item uses a distinct shade of the selection color; empty filler cells get no hover effect. Picker list items use compact padding (`var(--content-gap-within-inline)`). Every referenced CSS custom property resolves to a defined token; a floating panel gets a border plus shadow. Layout fixes that only one page needs go in that page's `.module.scss`, not the component stylesheet.
- No device detection for layout; responsive through CSS or deferred. After shrinking a widget, re-check text that fit before (long month names in a `<select>`).

## Jinja

- Every visible string is translated. Templates use `{% trans %}Layer 1{% endtrans %}` or `{% trans n=1 %}Layer {{ n }}{% endtrans %}`, not `gettext('...').format()`; the Jinja and JS catalogs are separate, so matching a JS string buys nothing.
- Blocks placed inside attributes trim whitespace (`{%- block name %}`) or move into the `{% set %}` above; a block that reads loop or local variables is `scoped`.
- Wording: hyphenate compound modifiers ("user-submitted data"), "yet" at the end ("does not have an account yet"), sentence case on buttons ("Add from search"), the terms the UI already uses ("authors").
- Reuse core macros (`format_event_date`) before hand-rolling.
- Inline scripts: `<script>` without `language`, no jQuery in new code (`document.querySelector`, `classList`, `domReady.then(() => ...)`), arrow functions. Jinja booleans are lowercase (`false`); `{%- trans %}` on its own line for long strings.
- Shared templates (`forms/_form.html`) never branch on one form's id; page-specific behavior lives with that page. No `XMLHttpRequest`: `indicoAxios` in JS modules, `fetch()` in the rare inline script, and preferably no inline request code at all.
- `{{- x -}}` where output is inline; `data-no-qtip` on `title` attributes that must not open a qtip.
- `url_for_plugin('.endpoint')` inside blueprints; shared URL values via `@blueprint.url_defaults`.
- Template names describe the page; shared markup moves to a macro partial (`_name.html`).
- Several possible parents: separate `{% extends %}` in an `if/elif` chain, not nested ternaries in one `extends`.
- Side menu items: weight `-100` for entries that go last (logs); positive weights for the rest.
- `_()` inside macro arguments (`{% trans %}` does not work there); plugin gettext in plugins.
- Every counter or list uses the same filtered accessor.
- Calls to action and links match the viewer's rights; a restricted role sees no link it cannot follow.
- A disabled button explains why in its own `title`, not through a separate info icon; every visible string, button text and table headers included, goes through `{% trans %}`. A cell with an icon next to a name gets `white-space: nowrap`.
- Links to objects use their named endpoint (`url_for('rb.booking_link', booking_id=...)`), never a path plus `modal=` query string.
- `url_for` with the locator object only (`url_for('.resend', entry)`), no redundant parent argument.
- Data attributes read from optional objects (`invitation.lock_email`) are guarded; load the page without that object.
- Attribute continuation lines align with the first attribute; no blank line after a block opener; tag contents indented; no collapsing of multi-line markup into one long line.
- Plugin output reuses the core look (the standard join button, not a raw URL); pick the best available template hook and note the better one for later.
- Default document templates carry no provider-specific logic (payment plugin fields) and no "Default" in the title users copy; fonts are generic families (the PDF renderer has no web fonts); labels are statements, not questions ("Add event logo"); an image field over a checkbox when a custom picture is plausible; unused template variables are removed. New data directories are added to the packaging manifest.
- Default receipt templates: copy field descriptions and options from the existing default template (affiliation toggle, address override), spell-check default texts, offer `{date_range}` with the one-day/multi-day logic plus `{start_date}` and `{end_date}`. Filters are named after what they do (`format_placeholders`), output is marked `| safe` on the expression instead of an `{% autoescape false %}` block.
- HTML emails: indent normally, `<h3>` for section titles, `<ul>` for lists, `<a>` for links (link the title), no `trim`/`indent` filters or blank-line hacks carried over from the text template.
- A custom element without content keeps its tags on one line (`<ind-x event-id="{{ event.id }}"></ind-x>`); markup that fits the line after attributes were removed goes on one line. Intentional empty elements are one-liners with one comment explaining why they exist. No XHTML self-closing tags (`<br>`, not `<br />`); check whether the renderer needs them before deviating. Attribute values are always quoted; an `alt` carries meaningful text or stays empty.
- `{% elif %}` and `{% else %}` align with their `{% if %}`; content inside `{% if %}` / `{% for %}` blocks is indented one level. `{% for day, entries in days.items() %}` when the body indexes the dict. Never name a template variable `session`; use `sess`. Macros used only inside their file are `_`-prefixed. Unused macro imports (`message_box`) are removed when their last use goes.
- Enum members compare by name (`entry.type.name == 'SESSION_BLOCK'`), never by raw value; dispatch uses an explicit `elif` per member, `else` only for "any other value". A macro name promises its argument type; several accepted types are dispatched explicitly with a comment, never probed (`x.object if x.object else x`); a macro that branches on the type throughout splits into one macro per type. A macro gaining a parameter updates every caller, including template-module calls from Python.
- Static text stays outside `{{ }}`; interpolate only the dynamic part (`.{{ c_id }} .inherited-bg-color {`), no `~` concatenation; conditional inline parts use `{%- if %}`. Joining values uses filters (`{{ parts | select | join(', ') }}`), not `loop.nextitem`. User strings interpolated into CSS (`content: '{{ event.title }}'`) are checked with quotes and line breaks; confirm autoescaping covers it or use `attr(data-*)`.
- Pass `event.tzinfo` to date helpers, not the `event.timezone` string. `format_skeleton` for ICU skeletons (`HHmm`, `EEEEdMMMM`); a `format=` pattern only for a literal pattern. Plural strings use `{% trans count=n %}...{% pluralize %}...{% endtrans %}`, not `ngettext()` in an expression. A `{% trans %}` block whose only content is a variable is removed. In HTML emails a list value is joined with `'<br>'|safe`; the URL goes on its own line after the translated sentence, never inside the `{% trans %}` block.
- A label the content makes obvious ("Location:" above an address) is dropped; no trailing-colon labels. Help text for user-supplied regexes shows `\b` boundaries and mirrors the target service's notation.
- A template that switches its base on a mode flag (`{% if preview %}{% extends ... %}`) becomes two templates, one in `display/` and one in `management/`. When a flow stops reloading the page, server-rendered explanations that assumed the reload go, and button labels that referred to them are reworded.
- Integration settings get their own `form_fieldset` and field tuple (`form.X_FIELDS`); the template gates the fieldset on the same config flag that removes the fields from the form. A settings section shows a `message_box('warning')` when exactly one of two fields a feature needs is set; the check is a controller helper passed to the template, computed in both the full page and the section refresh.
- A new `SideMenuItem` takes a weight no sibling uses; read the module's `_sidemenu_items` first.

## Verification

- Click through every page as every affected role; list what to hide (payments, ACL, tags, manage/clone/delete, customize list, logs, modify).
- Test in Firefox as well as Chrome (scrollbars, loaders).
- Admin menu entries sit in the section matching their topic (`user_management` for affiliations).
- Hover, truncate, empty, resize.
- Compare against the description's screenshot; attach your own.
- Test in Safari as well for `<dialog>`, click-outside and focus handling (navigation buttons must not close the dialog). Build with webpack and clear every new warning (duplicate side-effect imports, aliased imports of sibling modules).
- Try a widget near the viewport bottom, inside a centered modal, next to a sticky toolbar, disabled, inside and outside `.ui.form`, with a non-English locale, and while editing an existing record; its disabled, hover and font styling must match in every context. Check single-month, two-month and inline variants at their natural width.
- Keyboard-only pass: tab to the trigger, arrows across a month boundary, Escape, focus back on the trigger; screen reader pass on selection and mode change announcements.
